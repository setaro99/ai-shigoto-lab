事務所の移転が決まると、総務や営業事務には「取引先へのお知らせ、作っておいて」という仕事が回ってきます。定型文はネットで見つかりますが、実際に困るのは文面そのものより**中身の抜け漏れ**です。電話番号は変わるのか、旧住所への郵便はいつまで届くのか、請求書の送付先を変えてもらう必要はあるのか——このあたりが曖昧なまま送ると、あとから問い合わせが何件も来ることになります。

この記事では、移転のお知らせを「挨拶文」ではなく**取引先に行動してもらうための連絡**として整理し、AIで短時間に仕上げる方法を紹介します。

## 移転のお知らせで起きがちな失敗

- 新住所は書いたが、**いつから新住所で業務を始めるのか**が書かれていない
- 電話・FAX番号が「変わらない」のか「変わる」のかが読み取れない
- 請求書・納品物・郵便物の**送付先変更のお願い**を書き忘れ、旧住所に届き続ける
- 移転作業中の休業日や電話がつながらない時間を伝えておらず、相手を困らせる
- 来訪する相手向けの最寄り駅・駐車場などの情報がない

社員向けの移転周知（座席や荷物の梱包など）は[社内アナウンス文の記事]({{ site.baseurl }}{% post_url 2026-08-10-ai-shanai-announce %})で扱っています。この記事は**社外の取引先向け**に絞ります。

## 解決の考え方：先に「変わるもの一覧」を作り、文面はそのあと

移転のお知らせは、いきなり文章を書かせると、AIが「変わらない部分」まで勝手に補ったり、逆に大事な項目を飛ばしたりします。そこで2段階に分けます。

1. **事実の整理**：何が・いつ・どう変わるのかを表にする。不明な項目は「未確定」として残す
2. **文面化**：その表だけを材料に、メールと書面（はがき・挨拶状）の文面を作る

ポイントは、取引先にとっての情報を3種類に分けることです。

| 種類 | 中身 | 例 |
|---|---|---|
| 知らせるだけ | 相手は何もしなくてよい | 新住所、最寄り駅、移転の理由 |
| お願いする | 相手に手続きをしてもらう | 請求書の送付先、登録住所の変更 |
| 注意してもらう | 一時的に不便が出る | 移転作業日の休業、電話の不通時間 |

「お願いする」項目がいちばん読み飛ばされやすく、いちばん困る部分です。ここを本文で独立させるだけで、移転後の問い合わせはかなり減らせます。

## コピペ用プロンプト①：変わるもの一覧を作る

まず、手元のメモを貼り付けて整理してもらいます。メモは箇条書きでも、社内のメールをそのまま貼っても構いません。

```
あなたは総務の事務を手伝うアシスタントです。
事務所移転について、取引先に伝えるべき情報を整理してください。
まだ文面は作らないでください。

【手元のメモ（貼り付け）】
【例：12月14日（月）から新事務所で営業。新住所は○○市○○町1-2-3 ○○ビル5階。
電話番号は変わる、FAXは廃止。12月11日・12日は移転作業で休業。
旧住所あての郵便は転送届を出す予定。】

【お願いしたいこと】
1. 次の項目ごとに表で整理する（項目／内容／取引先にとっての種類）
   項目：移転日（新住所での業務開始日）、新住所、旧住所、電話番号、FAX番号、
   メールアドレス・Webサイト、移転作業に伴う休業・不通の日時、
   郵便物の扱い、請求書・納品物の送付先、来訪時の案内（最寄り駅・駐車場）、
   問い合わせ窓口
2. 「取引先にとっての種類」は「知らせるだけ／お願いする／注意してもらう」のいずれかにする
3. メモに書かれていない項目は推測で埋めず、「未確定（要確認）」と書く
4. 最後に、送る前に社内で確認しておくべき質問を箇条書きで3〜5個挙げる
   （例：電話の自動案内はいつまで流すか）
```

最後の「社内で確認しておくべき質問」が、このプロンプトのいちばんの使いどころです。「旧番号の案内メッセージはいつまで流れるのか」「年末の請求書はどちらの住所から出すのか」など、担当者が気づきにくい論点を先に洗い出せます。

## コピペ用プロンプト②：取引先向けのメール文面を作る

プロンプト①の表を確認・修正したら、それを貼り付けて文面にしてもらいます。

```
下の「確定した情報」だけを使って、取引先に送る事務所移転のお知らせメールを作ってください。

【条件】
- 件名は、受信一覧で内容が分かるように「【事務所移転のお知らせ】」で始め、移転日を入れる
- 本文の構成：挨拶 → 移転の案内（日付と結論を最初に）→ 新しい連絡先 →
  お願い事項 → 移転作業に伴うご不便のお詫び → 結び → 署名
- 新住所・電話番号などは本文中に埋もれさせず、【 】や箇条書きで見やすくまとめる
- 「お願いする」項目は「お手数ですが、次の変更をお願いいたします」として独立させる
- 「未確定」の項目は本文に入れない
- 情報にない移転理由や業績の話を作らない。移転理由が空欄なら
  「業務拡充に伴い」などの定型句も付けない
- 丁寧だが長すぎない文面にする（本文400〜600字程度）

【確定した情報】
【ここにプロンプト①の表を、修正後の内容で貼り付け】

【差出人】
【会社名・部署・担当者名】

出力は「メール文面」→「はがき・挨拶状に転用する場合に変えるべき点（3つ以内）」の順で。
```

移転理由の扱いを条件に入れているのは、AIが「業務拡大に伴い」「さらなるサービス向上のため」といった理由を自然に付け足しがちだからです。事実と違う理由を取引先に送るのは避けたいので、書かせない指示を明示しておきます。

## 送り分けると、さらに伝わる

取引先の中でも、知りたい情報は相手によって違います。全員に同じ文面を送ってもよいのですが、余裕があれば次のように一言変えると親切です。

- **請求書や納品物をやり取りしている相手**：送付先変更のお願いを冒頭近くに移す
- **来訪の多い相手**：地図のURLや最寄り駅、入館方法を添える
- **年に数回しか連絡しない相手**：要点だけの短い版にする

AIには「プロンプト②の文面を、来訪の多い相手向けに書き換えて。新しい情報は足さないこと」と続けて頼めば、骨格を保ったまま調整できます。

## 送信前のチェックリスト

- [ ] 新住所の番地・ビル名・階数、郵便番号を、賃貸契約書など元の資料と1文字ずつ照合したか
- [ ] 新しい電話・FAX番号に実際にかけてつながるか（移転前なら開通日を確認）
- [ ] 「移転日」が、新住所で業務を始める日として明確に書かれているか
- [ ] お願い事項（送付先変更など）の対象と時期が具体的か
- [ ] 署名・Webサイト・請求書のテンプレートなど、自社側の住所表記も更新予定に入っているか
- [ ] 一斉送信の場合、宛先をBCCにするなど社内の送信ルールに沿っているか
- [ ] AIが情報にない理由や表現を付け足していないか

社外向けの文面なので、敬語の言い回しが気になる場合は[敬語チェックの記事]({{ site.baseurl }}{% post_url 2026-10-04-ai-keigo-check %})のプロンプトで仕上げの点検をしておくと安心です。

## まとめ

- 移転のお知らせで困るのは文面より中身の抜け漏れ。先に「変わるもの一覧」を作る
- 情報を「知らせるだけ／お願いする／注意してもらう」に分け、お願い事項は本文で独立させる
- 不明な項目は「未確定」のまま残し、確定した情報だけを文面にする
- AIが移転理由などを付け足さないよう、条件で明示的に止める
- 送信前に住所・番号を元の資料と照合し、実際に電話をかけて確かめる

まずは手元の移転メモをプロンプト①に貼り、「社内で確認しておくべき質問」を出してもらうところから始めてみてください。確認すべきことが見えれば、文面づくりは数分で終わります。
